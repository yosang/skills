# Agent Rules (skills)

This workspace uses the skills defined in `skills`:

- **UI & Design System (`skills/ui-craft/SKILL.md`):** Follow the 3P framework (*Purpose, Principles, Personality*) and the 60-30-10 color budget. Use matte surfaces without multi-color `radial-gradient` aurora glows, cohesive OKLCH/tinted neutrals with soft dark-mode lightness (`22%` to `24%`), fluid `clamp()` typography capped at `62ch` line width, restrained radii (`6px` to `14px`), and viewport-aware media loading.
- **Copy & Tone (`skills/natural-copy/SKILL.md`):** Write direct, human prose without em dashes (`—` or `–`), mid-sentence colons (`:`) used to join clauses, colon-split headings (`Label: Heading` such as *"Utenfor skjermen: Fjell, telt og hunden"*), negative parallelisms ("not X, but Y"), compound modifier hyphens (`full-stack`, `cross-clinic`, `real-time`, `AI-assisted`), stiff essay verbs (`showcase`, `demonstrate`, `accumulate`, `arose`, `utilize`, `consolidate`, `eliminate`, `cumbersome`, `purged`), or literal idiom calques (*"stands and falls on"*). For Norwegian (`nb`) copy and voice scripts, use natural spoken Bokmål, retain standard English developer terms (`frontend`, `backend`, `fullstack`, `remote`, `soft delete`, `edge cases`, `state`, `loading og error states`, `accessibility`, `cookies`, `unique constraints`), avoid bureaucratic or textbook terms (`faktaforankring`, `målrettede tiltak`, `unike skranker`, `arbeidsminnet`, `stemmesyntese`, `applikasjonen`, `publikumssidene`, `medbygger`, `merkantil`), and drop hyphen clutter (no suspended hyphens like `turnerings- og bordplattform`, no `QR kode`/`AI versjon`/`3D modell` hyphens, and no hyphens glued onto code tokens like `.Include()-kall`). In personal, portfolio, and application copy, lead with human motivation before tech specs, group projects by real-world context, and never parrot a job posting's exact wording.
- **Architecture & Code (`skills/lean-architecture/SKILL.md`):** Lock constraints on paper and in `AGENTS.md` before coding, work in *Spike and Stabilize* cycles, make small frequent commits (never mixing refactoring and behavior changes in the same commit), keep a single source of truth for shared data, prefer deletion over addition, and document silent production gotchas in `README.md`.
